# Plancher mémoire P0 — Linux sous WSL2 (2026-11-05, indicatif)

Relevé **indicatif** (voir `docs/PERFORMANCE.md`) : Linux dans la machine virtuelle WSL2,
affichage WSLg. Même application au repos que le relevé Windows de référence : fenêtre
ouverte, aucun document, worker inactif. Ne pas en déduire de budget.

## Protocole

- `node scripts/measure-memory.mjs 10 5` après
  `npm --prefix apps/desktop run tauri -- build --no-bundle -- --locked`, build release du
  commit `9dfcc8a`, dépôt cloné dans le système de fichiers Linux (`~/`).
- 10 lancements successifs, relevé 5 s après le démarrage, arrêt par SIGTERM puis
  vérification que `pdf-worker` ne survit pas. 4 processus par lancement : shell
  (avec le processus UI de WebKitGTK), `pdf-worker`, processus web et réseau de WebKit.

## Environnement

Même PC que le relevé Windows (Intel Core i7-12700KF). WSL 2.5.10.0, noyau
6.6.87.2-microsoft-standard-WSL2, WSLg 1.0.66, Ubuntu 22.04.5 LTS, 32 GiB alloués à
la VM, WebKitGTK 2.50.4, Rust 1.99.1, Node 24.16.0.

## Lecture et limites

- Sous Linux, WebKitGTK exécute sa partie interface dans le processus du shell : le
  shell pèse donc bien plus que sous Windows, sans que le code Rust du projet en soit la cause.
- La PSS (327 MiB) répartit les pages partagées entre processus ; c'est l'indicateur à
  suivre sous Linux, avec la mémoire privée.
- Rendu par WSLg, GPU virtualisé : un Linux natif avec un autre environnement de bureau
  peut différer sensiblement. Le relevé CI `memory` (Ubuntu sous xvfb) donne un ordre de
  grandeur proche : 338 MiB de PSS.
